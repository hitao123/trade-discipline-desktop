# 极速成交补录与数据健康层设计

**日期：** 2026-08-23  
**状态：** 已确认，待实施计划  
**范围：** 本地 macOS 单用户 Plain Rule；只记录事实，不连接券商、不发送委托。

## 目标

1. 让用户在券商完成真实成交后，以尽可能少的操作补录，同时立即更新本地持仓、现金和盈亏。
2. 不让“快速”成为绕过纪律、删除历史或制造第二套账本的通道。
3. 将公开行情从“成功/失败”改为可判断新鲜度、来源和可用性的状态；旧数据绝不显示为实时。

## 非目标

- 不接入券商账户、下单、自动交易或自动导入成交。
- 不以公开汇率替代券商实际人民币结算金额。
- 不在后台高频轮询实时行情；实时页仍仅在用户手动刷新时请求。
- 不将缓存或过期行情用于价格提醒。

## 一、极速成交补录

### 设计原则

现有 `POST /api/executions` 已能以不可变成交事件重放持仓、现金和盈亏，并在无计划或违规时生成违规、冷静期与审计。极速补录只简化前端输入，必须复用这条正式账本链路；不得新建临时账本或稍后确认的影子成交。

### 交互

在“成交补录”页顶部增加“极速补录”卡片；完整成交表单仍保留，供关联计划、填写证据和补充详情。

极速卡片的默认输入为：

1. 证券；
2. 买入/卖出；
3. 数量（按标的最小交易单位预填）；
4. 成交均价。

成交时间默认为当前时间。本币成交金额由均价乘数量自动计算，不允许手工输入。A 股与 ETF 的人民币结算金额由成交金额预填，用户可以按券商回单改写；港股必须填写券商实际人民币扣款/到账，以保证现金账本准确。

计划关联、券商成交编号、卖出代码和证据放入“稍后补充”区域，不阻止极速保存。未关联合格计划、卖出缺少退出代码等情况依然按现有规则写入严重违规和冷静期；界面不阻止用户如实入账。

保存成功后立即显示：本次成交已入账、剩余现金、当前持仓、纪律分类、冷静期（如有）与“录错？追加冲正”入口。

### 待复盘

每次通过极速卡片保存的成交，都创建一条与成交事件关联的“待纪律复盘”项。它至少包含状态、创建时间、完成时间和用户的事后说明。复盘说明为：当时为什么下单、是否冲动、下次如何避免重复；不影响已发生的账本事实与违规分类。

待复盘项在成交页与每周复盘页可见。每周复盘提交前，必须处理本周期内待复盘项：填写说明或明确标记“已处理”。

### 港股汇率参考

保存港股极速成交后，系统可以按成交日期获取并保存 HKD/CNY 的公开参考汇率与来源时间，用于复盘时展示“参考折算”。它只是一条观察记录：

- 持仓现金始终以用户填写的券商实际人民币扣款/到账为准；
- 获取失败不阻止成交保存；
- 参考汇率不得反写实际结算金额或生成交易建议。

### 更正与审计

极速成交和完整成交使用同样的冲正流程。录错后只能追加冲正并填写原因，旧成交、违规和审计记录均保留。不得提供直接编辑已入账成交的功能。

## 二、数据健康层

### 健康模型

为每一个独立数据组件记录并返回结构化健康信息：股票榜单、ETF 榜单、持仓参考报价、A 股成交额、南向资金、实时股票榜单、实时 ETF 榜单和价格提醒报价。

每项健康信息至少包括：

- `state`：`live`、`delayed`、`cached`、`unavailable`；
- `source`：实际使用的公开来源或 `mixed-public`；
- `sourceTime`：来源数据时间；
- `lastSuccessfulAt`：最近一次成功本地保存时间；
- `message`：面向用户的简短中文说明；
- `detailCode`：用于本地诊断的稳定代码，不在普通页面展示原始 URL 或 EOF 文本。

现有 `errors` 字段迁移为兼容读取，新的状态不再以一个字符串集合表达所有模块问题。

### 新鲜度与交易时段

实时数据必须同时满足以下条件才可标为 `live`：

1. 当前处于 A 股连续竞价时段；
2. 数据源交易日等于上海时区当天；
3. 数据源时间在允许的新鲜度窗口内。

如处于工作日节假日、临时休市或来源仍返回上一个交易日，第二项会失败，系统必须降级为 `cached` 或 `unavailable`，不保存为实时快照。这样不依赖节假日表也能保证保守正确；后续可以加入交易日历来减少无效请求。

交易时段内当天但超出新鲜度窗口的数据标为 `delayed`，保留显示但不称实时。价格提醒采用更严格规则：仅在来源交易日为当天且报价未超过提醒新鲜度窗口时评估；否则明确记录“报价不可用，未评估提醒”，绝不拿缓存价格触发。

### 容错与来源

- 收盘股票/ETF 成交额榜单：东方财富为主，新浪为备用；成功的榜单应独立保存。
- A 股成交额：保留现有指数数据兜底；合成指标依据实际组成来源标记为东方财富推导、新浪推导或混合公开来源。
- 持仓报价和价格提醒：提供可插拔的报价备用来源。只有确认标的覆盖、币种和来源时间有效后才可使用；若备用源不可用，保留最近成功报价并明确降级。
- 单项失败不得让整页失败。例如榜单刷新成功而持仓报价失败，应显示“榜单已更新；持仓参考价暂未更新”。

### 界面与诊断

市场页在每个榜单或指标旁展示状态徽标，例如：

- `实时 · 新浪 · 10:32:08`
- `当日延迟 · 12 分钟前`
- `本地缓存 · 最后成功于 08-22 15:03`
- `暂不可用 · 可重试`

页面首部展示本次刷新摘要，而非拼接所有错误。详细错误（请求地址、HTTP 状态、EOF、重试次数）只保留在本地结构化日志和“数据诊断”折叠区；普通用户不需要看到长 URL。

## 数据与迁移

新增一次兼容 SQLite 迁移：

1. 为极速成交增加可查询的来源/待复盘关联，不修改既有成交事件的不可变语义；
2. 新增成交后复盘项及其完成记录；
3. 为行情刷新状态保存结构化健康信息；
4. 为港股成交参考汇率保存独立观察记录；
5. 保持所有现有榜单、市场指标、成交、冲正和缓存数据可读取。

迁移必须按真实旧数据库升级路径测试，不能只测试空库。

## 验收与测试

后端测试至少覆盖：

- 极速买入和卖出立即改变持仓与现金；
- 港股实际人民币结算优先于参考汇率；
- 无计划极速成交仍保存，并产生违规、冷静期、审计和待复盘；
- 冲正恢复账本但不删除原记录和待复盘痕迹；
- 当日工作时段收到前一交易日来源数据时，实时刷新不保存为 `live`；
- 榜单成功、报价失败时状态独立且缓存可用；
- 报价过期时不触发价格提醒；
- 新浪兜底的 A 股成交额具有正确来源标记；
- 用户界面不显示原始长 URL/EOF，诊断信息可在本地查看；
- 从当前 schema 的真实样本升级后数据保持可读。

前端测试至少覆盖极速卡片最小字段、港股结算字段、成功回执、待复盘提示，以及 `live`/`delayed`/`cached`/`unavailable` 的展示。

## 实施顺序

1. 先建立结构化行情健康模型和新鲜度校验，修复“旧数据标实时”和错误墙；
2. 加入持仓报价/提醒的安全降级与来源标记；
3. 增加极速补录卡片，复用现有正式成交写入；
4. 增加待复盘、参考汇率记录及每周复盘入口；
5. 完成旧库迁移、回归测试、打包与 macOS 冒烟验证。
