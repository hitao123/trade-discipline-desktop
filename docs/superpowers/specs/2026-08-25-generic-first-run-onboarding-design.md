# 通用首次启动向导与空白账户设计

日期：2026-08-25  
状态：已确认，待实施计划

## 背景

Plain Rule 的安装包本身不包含用户的 `discipline.db`，每台 Mac 都会在 Electron 的独立用户数据目录中保存自己的数据库。但是当前后端在新数据库迁移时会主动写入以下个人化默认内容：

- 20 万元初始资金；
- 腾讯、阿里巴巴证券；
- 腾讯 200 股、阿里观察 20 个交易日、中概科技 8 万元上限等规则；
- 腾讯、沪深 300、半导体设备、黄金、通信、中概互联网、现金等七项资产配置；
- 年末收益 10% 等个人目标。

因此，把当前安装包直接交给别人虽然不会带出已有成交和持仓，但新用户仍会看到不属于自己的默认方案。本次设计从数据初始化边界解决这个问题，而不是只在界面隐藏个人字段。

## 目标

1. 新安装用户首次启动时进入简短向导，完成前不进入主应用。
2. 新用户完成向导后得到完全空白的交易工作区，不出现任何腾讯、阿里、20 万或七项配置默认数据。
3. 已经使用中的数据库升级后保持全部账户、规则、成交、持仓和资产配置不变。
4. 通用用户只启用普适的损失与纪律约束，不被个人化的中概、腾讯和阿里规则限制。
5. 通用用户可从空白状态建立任意资产配置，不再被固定资产名称和固定数量限制。
6. 向导与后续设置的修改都保留审计记录，且初始化失败时不产生半套数据。

## 非目标

- 不提供登录、云同步、多人账户或设备间数据共享。
- 不把老用户的个人规则自动转换成通用规则。
- 不在首次向导中要求填写具体证券、持仓、收益目标或配置比例。
- 不增加“一键清空全部数据”；已有事实仍遵循不可变记录和审计原则。
- 不连接券商、不下单，也不把行情数据当作交易指令。

## 一、用户模式与首次启动状态

### 模式

本地数据库具有明确的初始化模式：

- `legacy`：升级前已经使用 Plain Rule 的数据库。继续使用现有个人规则和配置。
- `generic`：通过新首次启动向导创建的通用数据库。

模式一旦完成初始化就不可通过普通设置切换，避免通用规则与历史个人规则在同一个账本内混用。后续如果确有迁移需求，应单独设计可审计的迁移流程。

### 状态

新增单例用户资料，至少保存：

- `mode`：`legacy` 或 `generic`；
- `onboardingStatus`：`pending` 或 `completed`；
- 可投资总资金（分）；
- 最大可承受损失（分）；
- 预期持有期限；
- 启用市场集合；
- 首次完成时间和最近更新时间。

预期持有期限使用稳定枚举，例如：`under_6m`、`6_to_12m`、`1_to_3y`、`over_3y`。启用市场可多选：A 股、A 股 ETF、港股；至少选择一项。A 股股票与 A 股 ETF 分开开关，以便只做 ETF 的用户获得更干净的界面。

## 二、升级与空库识别

### 识别原则

不能在建完全部旧表后再根据“表是否存在”判断新老用户，因为全新数据库也会经过建表流程。存储层必须在迁移开始前捕获数据库来源：

- 数据库文件不存在，或不存在任何已应用版本和业务事实：视为全新数据库；
- 已有旧 schema 版本、账户、规则或业务事实中的任意一类：视为既有数据库。

这个判定只在升级事务开始时执行一次，并作为迁移上下文使用。

### 既有数据库

升级既有数据库时：

1. 新增用户资料记录，写入 `legacy + completed`；
2. 从现有账户和规则读取资金与最大损失，尽可能回填资料字段；
3. 无法可靠推断的持有期限和市场范围使用兼容值，不影响原功能；
4. 不改写或删除账户、规则版本、证券、计划、成交、持仓、配置和审计；
5. 不重新执行任何个人默认种子。

### 全新数据库

全新数据库迁移只创建结构和 `generic + pending` 状态，不写入：

- 账户和初始现金；
- 规则版本；
- 腾讯、阿里或其他证券；
- 观察名单、交易计划、成交、持仓或复盘；
- 资产配置资料、配置版本或市值事件。

现有 `Migrate` 中无条件写入个人种子的逻辑必须拆除。老用户保留数据依赖迁移兼容，而不是继续对所有空库执行种子。

## 三、首次启动向导

### 启动门禁

应用启动并确认本地后端可用后，首先读取初始化状态：

- `pending`：只展示向导，不渲染侧边栏、今日页或其他业务页面；
- `completed`：正常进入主应用；
- 状态请求失败：展示可重试的本地启动错误，不误判为已完成，也不创建默认数据。

路由不能通过手工输入地址绕过门禁。主应用初始化依赖明确的完成状态，而不是只靠首页重定向。

### 三步交互

第一步“风险边界”：

- 可投资总资金；
- 最大可承受损失；
- 即时显示最大损失占总资金比例，仅用于理解，不替用户判断是否合理。

第二步“使用范围”：

- 预期持有期限；
- 启用市场：A 股、A 股 ETF、港股，可多选。

第三步“空白开始”：

- 明确说明数据只保存在本机；
- 明确说明不会连接券商或自动下单；
- 明确说明不会预设证券、持仓、收益目标和资产配置；
- 用户确认后完成初始化。

### 校验

- 总资金必须大于零；
- 最大可承受损失必须大于零且小于总资金；
- 必须选择持有期限；
- 必须选择至少一个市场；
- 金额以字符串输入并在边界转换成整数分，避免浮点误差；
- 重复点击提交只允许产生一次初始化结果。

向导支持在步骤间返回修改。未最终提交前不写业务数据；退出应用后再次启动仍从向导开始。

## 四、原子初始化与接口

建议提供两个专用接口：

- `GET /api/onboarding`：返回模式、状态和已保存的基础资料；
- `POST /api/onboarding/complete`：校验并原子完成通用初始化。

完成接口在一个数据库事务中：

1. 确认当前状态仍为 `generic + pending`；
2. 写入基础资料；
3. 创建本地人民币账户和与总资金相等的初始现金事实；
4. 创建第一版通用纪律规则；
5. 写入初始化审计事件；
6. 最后把状态更新为 `completed`。

任何步骤失败全部回滚。重复提交已完成资料返回稳定的冲突响应，不覆盖旧数据。前端收到冲突后重新读取状态；如果实际上已经完成，就直接进入主应用。

## 五、通用纪律规则

### 通用规则保留的约束

通用模式保留：

- 最大可承受损失红线；
- 损失预警线，默认取最大可承受损失的 75%；
- 交易后冷静期和冲动记录；
- 计划、证据、退出条件、情绪、违规和每周复盘；
- 市场最小交易单位、真实成交事实和不可变审计。

所有金额提示必须来自实际资料或规则，不能再写死“2 万”“8 万”等个人数字。

### 通用模式禁用的个人约束

通用模式不启用：

- 腾讯与阿里的最大股数；
- 腾讯必须等待阿里观察 20 个交易日且纪律分达到 90；
- 中概科技敞口固定上限；
- 腾讯、阿里的预设证券和每手事实；
- 与用户个人资产方案绑定的文案。

规则快照需要带有明确的规则模式或能力开关。推荐新增 `profileMode`，全新通用规则写入 `generic`；旧规则 JSON 缺少该字段时按 `legacy` 处理，从而保证升级后原有个人规则仍然生效。

规则引擎、成交校验、今日页和设置页都基于同一模式判断，不能出现“后端已通用但前端仍显示腾讯门槛”或相反的情况。

## 六、设置与修改历史

通用用户在“规则与设置”中可以修改：

- 可投资总资金；
- 最大可承受损失；
- 预期持有期限；
- 启用市场。

保存时必须填写修改原因，并在一个事务中：

1. 写入新的基础资料版本或审计前后快照；
2. 对涉及金额的通用规则创建新规则版本；
3. 保留旧计划和旧成交所引用的原规则版本；
4. 返回最新资料和当前生效规则。

总资金修改表示纪律和配置的参考基准，不重写历史现金，也不伪造入金/出金。若用户需要调整真实现金，应通过独立的资金事实入口处理。

老用户的设置页继续显示现有个人规则，并增加“个人历史模式”说明，不强制进入向导，也不自动改成通用字段。

## 七、空白业务页面

通用初始化完成后进入“今日”，以下内容必须为空：

- 观察名单；
- 交易计划；
- 成交补录历史；
- 持仓；
- 每周复盘；
- 资产配置。

空页面使用行动型空状态说明下一步，但不自动创建证券或示例数据。例如资产配置显示“尚未建立资产配置”和“开始配置”，而不是展示腾讯等示例行。

市场榜单仍可通过公开行情获取，因为它属于公共观察数据，不属于个人预设。榜单证券只有在真实刷新、手动解析或用户选择时才进入本地证券库。

## 八、通用资产配置

### 空白开始

通用模式读取资产配置时不得调用当前的个人化 `EnsureInitialAllocation`。没有配置资料时，接口返回明确的 `notConfigured` 状态，页面展示空状态。

点击“开始配置”后创建空白草稿：

- 初始基准资金默认引用向导中的可投资总资金，用户可修改；
- 年化或阶段收益目标默认为空，不自动设置 10%；
- 截止日期默认为空；
- 配置项目列表默认为空。

### 任意配置项目

用户可添加、删除和排序任意配置项目。每项至少包含：

- 稳定内部键，由系统生成；
- 名称；
- 目标占比；
- 可选的目标股数；
- 可选关联证券；
- 类型：持仓类或现金类；
- 可选买入规则、卖出规则和备注。

配置中最多有一个现金类项目，它自动关联账本现金而不关联证券。持仓类项目可关联零到多个证券，同一证券最多归属一个项目。未归类持仓继续独立显示并计入总资产，避免静默遗漏。

保存要求所有目标占比合计为 100%。允许先保存草稿，但只有满足合计与映射约束的版本才成为当前生效配置。每次修改填写原因并生成新版本。

### 旧资产配置兼容

`legacy` 模式继续使用现有七项配置和现有联动，不要求立即补充新字段。旧配置中键为 `cash-fund` 的项目兼容解释为现金类；其他旧项目解释为持仓类。新字段缺失时的兼容转换只发生在读取层，不改写历史 JSON。

## 九、前端组件边界

- `App`：只负责等待后端、读取初始化状态并在向导与主应用之间切换。
- `OnboardingView`：独立承载步骤、客户端校验、提交和错误恢复，不依赖主应用侧边栏。
- 主路由：只在初始化完成后挂载；设置页根据模式显示通用或历史个人规则。
- `AllocationView`：独立处理 `notConfigured`，不能依赖首次向导替它创建配置。
- 前端类型：为初始化资料、市场选项、期限和未配置资产状态提供明确类型，不以任意对象传递。

界面沿用现有纸张、细边框、黑色主按钮和红色强调风格。向导以易懂语言为主，不展示数据库、schema 或规则 JSON 等实现细节。

## 十、错误处理与恢复

- 本地后端未启动：向导展示“本地服务尚未就绪”并允许重试。
- 初始化校验失败：定位到具体字段，保留已经填写的其他步骤。
- 初始化事务失败：保留 `pending`，不进入主应用，不留下账户或规则残片。
- 初始化已完成但前端超时：下次读取状态后进入主应用，不重复创建现金。
- 既有数据库迁移失败：数据库事务回滚，原数据保持不变；不得为绕过错误而新建空账户。
- 资产配置尚未建立：返回空状态而不是服务器错误。
- 通用规则缺少必要字段：拒绝保存新规则，同时继续保留上一版有效规则。

## 十一、隐私与分发说明

- 安装包不包含用户数据库、截图、成交或配置。
- 每位 macOS 用户的数据位于其自己的应用用户数据目录。
- 截图 OCR 继续只在本机处理，不上传。
- 首次向导明确提示“仅本机保存”，但不宣称数据经过加密；本次不新增数据库加密。
- 构建发布前增加产物检查，确保 DMG 和应用资源中不存在 `discipline.db`、用户截图或导出的个人文件。

## 十二、验证范围

遵循“少而关键”的测试原则，不新增大量重复测试。

后端关键用例：

1. 全新临时数据目录迁移后为 `generic + pending`，且账户、规则、证券和资产配置均为空。
2. 当前 schema 10 的既有数据库升级后为 `legacy + completed`，原有表数据和规则快照不变。
3. 完成向导在一个事务中创建资料、账户、初始现金、通用规则和审计；模拟失败时全部回滚。
4. 重复完成初始化不会重复创建现金或覆盖资料。
5. 通用规则不触发腾讯顺序门槛、中概敞口和个股股数上限，但仍执行最大损失红线。
6. 通用资产配置初始未建立，随后可以保存任意持仓类项目和一个现金类项目。

前端关键用例：

1. `pending` 时只显示向导，不能进入主页面；`completed` 时跳过向导。
2. 三步校验、返回修改、提交失败恢复和成功进入今日页。
3. 通用设置页不显示腾讯、阿里或中概个人规则。
4. 资产配置未建立时显示空状态，创建后支持任意项目。

最终执行现有 Go 测试、前端测试、类型检查、生产构建和 macOS 打包冒烟，并使用全新临时用户数据目录做一次首次启动验证。不得用开发者自己的真实数据库验证迁移写操作。

## 验收标准

- 新用户首次打开只能看到启动向导。
- 完成向导后，观察名单、计划、成交、持仓、复盘和资产配置全部为空。
- 新用户任何页面都不出现腾讯、阿里、20 万、8 万中概上限、20 日观察或年末 10% 等默认内容。
- 新用户可以从空白状态自行建立任意资产配置。
- 老用户直接进入现有应用，所有数据与个人规则保持不变。
- 初始化中断或重复提交不会产生重复账户、重复现金或半套规则。
- 分发产物不包含开发者数据库或个人文件。

## 实施边界

本功能将跨越存储迁移、初始化服务、规则模式、资产配置空状态、前端门禁与设置页。实施时按“先数据安全与后端原子性，再前端向导和通用配置，最后全量验证与打包检查”的顺序进行。

本规格不授权提交、合并、清空现有数据库或覆盖当前 DMG；这些动作继续遵循当前工作区约束。
