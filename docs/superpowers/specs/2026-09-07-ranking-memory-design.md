# 成交额榜单变化记录：产品审视与第一版设计

日期：2026-09-07。状态：方案待实现。分析对象为当前工作区代码（含未提交修改），并非已安装版本的运行验收。本轮只写文档，未运行应用、联网验证行情源或更改业务代码。

## 产品取舍

核心价值：替用户保留昨天，解释今天的变化。先做可信的收盘榜单历史，再考虑盘中同时间比较。它是本地研究记录工具，不扩展为行情终端或交易推荐。

第一版交付：历史日期切换、较上一交易日收盘排名变化、新进榜、连续在榜天数、ETF 跟踪指数／类别标签，以及带日期与排名的观察理由。

不做：盘中排名变化、成交额倍数、板块热度评分、推送、定时采集、云端同步、自动补齐全市场历史、交易规则重构。实时页保留现有手动查看能力，不显示无法计算的比较指标。

示例名称、代码、数量仅为示意。

- 排名并入名称单元格，去掉逐行重复交易日和收盘价；保留名称、成交额、涨跌幅、排名变化、连续在榜。价格在走势详情显示。
- 收盘表头明确“较上交易日收盘”，不写“较昨日同时”；实时表头为“截至当前成交额”，不显示比较列，统一提示“尚无同时间历史对比”。
- 股票与 ETF 各自保存日期选择；切换时使用该榜单可用日期，不能混用另一榜单日期。按钮称“上一条记录”，不把跨缺失日的记录叫“上一交易日”。
- 选看历史后刷新只更新最新数据，不悄悄切走历史日期；提供“有新数据，回到最新”。
- 首次使用展示“从首次成功保存开始积累历史”；缺上一交易日时显示具体缺失日期，不把前一条本地记录冒充昨日。
- 来源、缓存状态、数据截至时间保持可见；版本及技术详情折叠。概览失败不影响有效榜单；状态按当前股票／ETF 分开。
- 不增加筛选器、热度评分或第二个历史菜单。通过日期选择及两项摘要验证用户是否愿意回来查看。

## 数据定义（实现合同）

### 比较资格

快照需满足：close 模式、有效同一交易日、来源支持该排行榜口径、去重后完整 Top20、成交额有效且排序稳定、过滤版本一致、收盘时间可验证。不能用抓取时间替代行情时间。

第一版保守策略：公开源收盘数据至少在上海时间 15:10 后抓取，且每行来源时间为其交易日 15:00 或之后、无未来时间；来源不能证明收盘完整性则标记未验证。这个缓冲时间是产品质量门槛，不是交易所时间规则。后续若支持停牌等特殊时间戳，只能凭 provider 提供的完整日终语义放宽，不能直接兜底成收盘。

只有 20 行仍不足以证明口径正确：provider 必须明确候选按成交额降序、过滤后已得到 20 个合格标的；排序统一为成交额降序，金额相同按 market/code 升序。股票保持当前排除 ST/退市标记的口径；ETF 保持当前排除债券/货币等的口径，并在页面说明“按当前筛选口径”。口径版本变化不跨版本比较。

旧记录默认 legacy_unverified，可回看但不参与比较；不得依据 fetchedAt 自动升级为已验证。CSV 维持现有导入流程，标记 manual_unverified，本版不让用户一次勾选便宣称全市场完整。非法／不完整的新数据不得覆盖最后一份可比快照。

### 交易日与版本

新增独立 A 股日历接口：PrevTradingDay(date) 与覆盖范围，附来源及更新时间；覆盖范围内包含工作日休市。初始化使用交易所公布的 2026 年安排，执行者需查验官方来源并保存引用；超范围返回 unknown，不猜测。测试使用固定日历，不联网。不得为本功能修改纪律引擎中其他交易日算法。

同一日期、kind、mode、口径取最新一份合格版本；旧版本保留，修正后动态重算对比。不依靠刷新次数计天数。现有 version 唯一约束跨 mode，共享递增，第一版保留以免引入唯一键冲突；查询必须带 mode 条件。

### 排名、新进榜、连续天数

- rankDelta = previousRank - currentRank；正数 ↑N，负数 ↓N，0 持平。
- 上一交易日完整可比且该证券不在其中：新进榜；previousRank 与 rankDelta 均为 null，不假造第21名。不表示历史首次入榜。
- 缺上一交易日／日历未知／口径不一致：不可比较，显示“—”及原因；不能判定新进榜。
- 连续天数只统计按交易日连续的合格收盘榜单；当前入榜日计1，重复刷新不累加。
- 向前遇到完整可比榜单且该证券缺席，才得到精确长度；遇到记录缺口、日历覆盖边界或口径边界，显示“≥N天（更早记录不足）”。当前快照本身未验证时显示“—”，不计1。
- 连续≥3日摘要可以包含已确认至少3日的记录；新进榜计数仅在基准完整可比时显示。不把 null 格式化为0。
- 离榜列表暂不展示；不能对离榜标的填写不存在的当日金额或跌幅。

### ETF 标签

使用独立只读映射，key = market + code，字段为 trackingIndexId/Name、assetCategory、sourceURL、verifiedAt。指数 ID 需带编制机构命名空间。资产类别固定为股票／债券／货币／商品／跨资产／未知，沿用现有排除逻辑，不因标签改变榜单范围。

执行者从基金管理人产品页或基金文件核验少量常见 ETF；无法核验则“待补充”。禁止仅按简称推断指数。以指数标签为优先展示，缺指数时显示类别；标签可查看来源。相同指数只是标签相同，本版不合并成交额、不生成板块评分、不按资产类别推断同指数。

## 差异化与后续顺序

1. 可信的昨日记忆：能回答“这只为何今天值得继续研究”，是第一版验收核心。
2. 低操作成本：默认打开最新本地记录、日期切换不请求公开源、关注状态可见。
3. 观察理由带上下文：保存加入当时的实际日期、模式、排名及比较结果；后续数据修正不改写原观察理由。
4. 后续再考虑从观察名单预填计划证券、近5日入榜次数、离榜回看。
5. 盘中同时间比较必须另立方案：固定时间截面、上一交易日同截面、完整榜单及历史覆盖、缺样本规则。金额倍数须使用相同标的过去N交易日同时间累计金额平均，排除今日；不能只拿入榜日平均，也不能用零成交额的备用日线当真实零值。

## 验证产品价值

先用固定多日数据验证用户能在一次日期切换内回答“谁新进、谁持续、ETF是否重复指数”；再以5个实际保存交易日试用记录观察。确认用户回看历史、利用变化信息加入观察，而非只刷新榜单。无需加入遥测，采用简短人工试用记录；这是待验证假设，不声称已经建立留存差异。
