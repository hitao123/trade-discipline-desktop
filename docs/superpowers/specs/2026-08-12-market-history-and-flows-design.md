# 市场历史行情与资金流图表设计

## 目标

在现有 macOS 单用户本地应用中，为“市场榜单”增加可追溯的历史数据能力：

- 查看榜单证券近 1 个月或 3 个月的日收盘价折线图。
- 查看沪深 A 股每日成交额折线图。
- 查看南向资金每日成交净买额折线图，正数表示净买入，负数表示净卖出。
- 将成功获取的数据保存在本机 SQLite；公开接口暂时不可用或日后发生变化时，仍能查看已经保存的历史。
- 只在用户刷新榜单或选择证券走势时请求数据，不建立后台轮询，不连接券商，也不执行真实交易。

## 已确定的数据口径

1. “A 股成交量”按更适合跨日期比较的“沪深两市成交额”实现，单位为人民币。范围沿用当前榜单的沪深市场，不包含北交所。
2. 沪深成交额由上证综合指数和深证综合指数日线中的成交额相加，分别代表上海和深圳市场口径。
3. 南向资金使用“成交净买额”，即港股通（沪）与港股通（深）的买入成交额减卖出成交额后相加。它不与“已用额度/当日净流入”混用。
4. 图表范围按自然月过滤：1 个月和 3 个月。首次补齐请求最多取 120 个交易日，保证三个月窗口覆盖节假日。
5. 所有金额进入数据库前转换为整数分，避免浮点累计误差；图表展示时再格式化为亿元。

东方财富页面说明南向资金为港股通（沪）与港股通（深）之和，且资金数据默认以人民币计价：<https://data.eastmoney.com/hsgt/hsgtV2.html>。

## 方案比较

### 方案 A：完全在线读取，不保存

优点是代码和数据库最简单。缺点是每次打开都依赖接口，接口字段或地址变化后历史图表会立即失效，也无法比较过去某天看到的数据。该方案不满足长期可追溯要求。

### 方案 B：刷新榜单时批量补齐全部 30 只证券

优点是每一行都能立即显示迷你走势图。缺点是一次刷新会产生约 30 次证券历史请求，外加市场概览请求；在本地后端 30 秒响应窗口内容易超时，也更容易触发公开接口的访问限制。该方案与“不要让后端一直请求”的要求冲突。

### 方案 C：市场概览增量保存，证券走势按需补齐（采用）

刷新榜单时同时更新沪深成交额和南向成交净买额；用户在榜单中选择某只证券后，才获取该证券最多 120 个交易日的数据并永久缓存。同一证券同一交易日已有新鲜数据时直接读取本地缓存。

该方案把一次正常刷新控制在少量请求内，又能在用户真正查看证券时立即补齐三个月历史。榜单表格增加“查看走势”选择动作，选中的证券在表格上方显示一张较清晰的折线图，而不是为每行同时发起请求。

## 数据源与兼容策略

### 当前数据源

- 收盘成交额榜单：继续使用 `push2.eastmoney.com/api/qt/clist/get`。
- 证券日线与沪深市场日成交额：使用东方财富历史日线接口 `push2his.eastmoney.com/api/qt/stock/kline/get`。
- 南向资金历史：使用东方财富数据中心 `RPT_MUTUAL_DEAL_HISTORY` 报表，分别读取港股通（沪）和港股通（深）后按交易日合并。

这些网页数据接口不视为长期兼容的正式开发者契约。提供者、字段和 URL 必须封装在 Go 的 `market.Provider` 边界内，服务层、数据库和前端不能依赖原始字段名。

### 请求限制

- 不建立定时器或后台轮询。
- 同一次市场概览更新最多并发少量独立请求；证券历史一次只请求用户当前选择的一只。
- HTTP 请求带明确超时、浏览器风格的 `User-Agent` 和来源页标识。
- 不在失败后快速循环重试；用户可稍后手动刷新。
- 15:00 前不把当天沪深数据当作收盘数据；16:20 前不把当天南向数据当作完整收盘数据。

### 失败回退

- 任一数据源失败时，不删除或覆盖本地成功数据。
- 市场榜单、沪深成交额、南向资金和证券历史分别报告错误；其中一项失败不阻止其他项保存。
- 前端显示“当前显示本地缓存”和最后成功更新时间，而不是把旧数据伪装成刚更新的数据。
- 如果历史接口字段改变导致解析失败，返回可读错误并保留原始缓存。

## 数据模型

新增两个追加观察表和必要索引。数据点不原地覆盖；当公开来源修正某个交易日的数据时，写入新的观察记录。读取时选择该交易日最新一次成功观察，因此旧值仍可审计。

### `market_daily_bar_observations`

- `id`：观察记录 ID。
- `market`、`code`：证券标识。
- `trade_date`：交易日。
- `close_minor`：收盘价最小货币单位。
- `turnover_fen`：该证券或指数成交额（分）。
- `source`、`source_time`、`fetched_at`：来源与获取时间。
- 唯一约束覆盖证券、交易日、值和来源，完全相同的数据重复获取不会产生重复行。

### `market_metric_observations`

- `id`：观察记录 ID。
- `metric`：`ashare_turnover`、`southbound_net_buy`，并保留分项 `sh_turnover`、`sz_turnover`、`southbound_sh_net_buy`、`southbound_sz_net_buy`。
- `trade_date`、`value_fen`：交易日和金额（分，可为负数）。
- `source`、`source_time`、`fetched_at`：来源与获取时间。
- 唯一约束覆盖指标、交易日、值和来源。

每次成功同步还向现有 `audit_events` 追加一条摘要，记录数据类型、插入数、重复数和覆盖的日期范围，不保存完整自由文本。

数据库 schema 版本从 1 提升到 2。迁移必须幂等，旧版 `discipline.db` 启动后自动创建新表，现有交易、计划和审计数据保持不变。

## Go 后端边界

### 领域类型

- `DailyBar`：交易日、证券键、收盘价、成交额、来源时间。
- `MarketMetricPoint`：交易日、指标、金额、来源时间。
- `InstrumentHistory`：证券键、范围、数据点、缓存状态、最后成功更新时间和可选错误。
- `MarketOverview`：沪深成交额序列、南向成交净买额序列、缓存状态和分项错误。

### Provider 接口

在现有 `FetchRankings`、`FetchQuotes` 之外增加：

- `FetchDailyBars(ctx, key, limit) ([]DailyBar, error)`
- `FetchMarketMetrics(ctx, limit) ([]MarketMetricPoint, error)`

东方财富解析只存在于 `backend/internal/market`。服务测试使用本地 fake provider，网络响应解析测试使用 `httptest.Server`，自动测试不访问互联网。

### Store 接口

- 追加证券日线观察并返回插入/重复统计。
- 追加市场指标观察并返回插入/重复统计。
- 查询指定证券最近 3 个月每个交易日的最新观察。
- 查询两个概览指标最近 3 个月每个交易日的最新观察。
- 写入一条同步审计摘要。

### Service 与 HTTP API

现有 `POST /api/market/refresh` 保持兼容，并在刷新榜单后尝试刷新市场概览。返回值增加 `overview` 和按数据源区分的 `errors`，旧字段 `stock`、`etf` 不变。

新增：

- `GET /api/market/overview?range=1m|3m`：只读取本地缓存。
- `GET /api/market/history?market=SH&code=600000&range=1m|3m`：只读取本地缓存。
- `POST /api/market/history/refresh`：接收 `market`、`code`，按需获取最多 120 个交易日、追加保存并返回三个月数据；失败时若有缓存则返回缓存和错误说明。

证券选择触发的刷新与榜单刷新分离，避免一次榜单请求访问全部证券历史。

## Vue 组件与数据流

### 视觉与内容方向

- 视觉主张：延续现有纸张、墨色和单一砖红强调色；图表轻量、克制，以数据判断为主，不改造成卡片拼盘。
- 内容顺序：页面标题与刷新状态 → 两张市场概览图 → 股票/ETF 标签 → 当前选中证券走势 → 榜单表格。
- 交互：1 个月/3 个月切换；点击榜单“查看走势”更新选中状态；折线和数值标签使用短促淡入及选中行过渡，并尊重系统减少动画设置。

### 组件图

- `MarketView.vue`：只组合功能区、连接 composable，并处理“加入观察”动作。
- `useMarketHistory.ts`：持有榜单、概览、当前证券、范围、加载状态、缓存提示和 API 副作用。
- `MarketOverviewPanel.vue`：展示沪深成交额与南向成交净买额两条独立序列，不请求数据。
- `InstrumentHistoryPanel.vue`：展示选中证券标题、范围切换、缓存状态和收盘价图，不请求数据。
- `MarketLineChart.vue`：通用、无依赖的 SVG 折线图；接收已格式化的数据契约，支持正负零轴、空状态和无障碍摘要。
- `MarketTable.vue`：继续只负责展示；新增 `selectedKey` 属性和 `select-history` 事件，不直接请求历史数据。

所有状态由父级/composable 管理，子组件只接收类型化 props 并发出类型化事件。图表使用原生 SVG，不引入新的图表依赖。

## 图表行为

- 收盘价图纵轴按当前窗口最小值到最大值缩放；只有一个点时显示居中点而不是除零。
- 沪深成交额使用亿元格式。
- 南向净买额有明确零轴，正值使用现有砖红色，负值使用现有绿色；颜色只辅助判断，文本同时显示正负号。
- 横轴只标记首尾日期和必要的中间刻度，避免三个月数据拥挤。
- 鼠标悬停或键盘聚焦数据点时显示日期和精确值。
- 没有缓存时显示“选择证券并获取走势”；接口失败但存在缓存时继续画图并显示缓存提示。

- 图表只有一个点、全相同值、跨零值时 SVG 坐标有效。
- 保持“只能加入观察、不能下单”的现有约束。

## 验收标准

1. 用户刷新收盘榜单后，沪深成交额和南向成交净买额成功数据写入本地；应用重启后无需联网仍可显示。
2. 用户从股票或 ETF 榜单选择一只证券，可查看近 1 个月和 3 个月收盘价；同一天再次查看优先使用本地数据，不持续请求。
3. 任一公开数据接口失败不会删除最后一次成功数据，页面明确显示缓存时间和失败项。
4. 同一交易日来源数据发生修正时，旧观察仍保留，默认图表使用最新观察，审计摘要可看到同步发生过。
5. 当前榜单前 20/ETF 前 10、加入观察、CSV 备用导入和交易纪律流程保持兼容。
6. 不新增券商连接、自动交易、投资建议或后台定时任务。

## 本次不做

- 不给榜单 30 行同时预加载或绘制 30 张迷你走势图。
- 不预测涨跌，不生成买卖信号。
- 不接入需要密钥的商业行情源。
- 不把北向资金纳入本次图表。
- 不自动清理历史观察；数据量按单用户三个月到长期增量规模保留。
